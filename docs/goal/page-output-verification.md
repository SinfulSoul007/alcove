# Page output verification — in development

This increment adds native user-invoked print, PDF and WebArchive commands. The full browser/Arc fidelity goal remains active. There is no public0.6.2 download yet.

Task1's initial missing interfaces have RED evidence. Its coordinator tests exercise real temporary-file writes and owned, never-shown windows, replacing only capture/presentation timing. Four later failing cases exposed cross-window status and discarded background results; the coordinator now keeps prepared output for its original window and routes errors through native window-owned presentation rather than shared browser status. All42 component checks pass without diagnostics; existing Quick native lifecycle checks pass16.

Task2's File-menu/composition APIs were tested before wiring. Fifty-five focused checks now cover actual native menu registrations and explicit window targeting across primary/split/Peek/Quick/private contexts, blank/unrelated targets and retained normal-owner fallback. Key-window state is substituted only on owned fixtures; no live keyboard/menu success is inferred.

Seven actual WebKit checks generate full-document PDFs, including text below the viewport, and WebArchives with distinct document markers. The saved archive is consumed by a separate nonpersistent WK view. The real atomic background writer saves selected temporary files. Native print-operation construction requires its print panel and retains the real page title; the first check failed because the old suffix removal left .pdf on that title. Save-panel construction restricts file types. No real native dialog or printer is operated, and private fixtures read no normal keys or metadata.

Accepted file writes and native print operations now have application lifetime independent of their window jobs. Closed or changed sources receive generic nonmodal failure results without captured URL/title/destination data. A pending error for a document falls back to this result when that document closes or is replaced. Normal Quit waits for fast output quietly; longer work offers Wait, Then Quit / Quit Without Finishing / Keep Browsing. Waiting includes newly accepted output until the operation set drains; a file failure cancels that Quit. Native print cancellation drains without inventing a file failure. Repeated and synchronous presentation callbacks are identity guarded, and no application reply precedes its native termination decision. Result/Quit windows cannot inherit a background normal store for page shortcuts; settings/updates/new-window commands remain available.

Source identity is developing0.6.2-preview.1/build9, metadata format3 unchanged. Only `com.apple.security.print` is added to the previous entitlement set. The complete suite passes633 browser checks with zero failures/compiler diagnostics. Optimized arm64 and x86_64 bundles pass strict ad hoc signature/hardened-runtime verification, exact six entitlements and exact version/build/tag/minimum-OS metadata. One fresh whole-branch review and source CI remain required; no new public preview has been published. The native visual/dialog/printer, minimum-OS/Intel, quarantined-install, website-print-button, archive-opening, audit/performance and full Arc gates remain open. Implementation rulings and final review results will be collected here before the plan workspace is removed.

## Implementation decisions

- Ruling: skip an unchanged full baseline rerun — exact public source/CI already verifies the current browser code, and only design/plan files are new — cost if wrong: an environmental baseline difference can first appear in the new focused/full gates.

- Ruling: retain standing in-place/main execution and existing publication authorization — user's established preference supersedes skill approval menus — cost if wrong: less integration isolation; preserve per-task commits and one final fresh reviewer.

- Task 1: Ruling: preserve a prepared export until its own unchanged window regains focus and defer output errors to that same window/document — an asynchronous SDK result must neither interrupt another window nor silently discard the explicit save request/error — cost if wrong: prepared bytes can remain in memory while waiting for native focus; close/ownership revalidation and observer cleanup remain required. Pending results are not persisted.

- Task 1: Ruling: output errors must use native window-owned presentation rather than the shared store status — the store can serve multiple profile windows, so focus checks alone do not restrict which views display a shared message — cost if wrong: native error-sheet/key restoration behavior still needs direct UI verification. The environment gains reportError(String,NSWindow); success creates no modal acknowledgment.

- Ruling: add Task3 before final review/publication and move the whole-suite/build gates there — accepted async file IO must remain tracked after close and through normal Quit, otherwise a closed-window write failure or immediate Quit can silently lose an accepted export — cost if wrong: more application-lifetime state and native result/Quit UI to verify. Keep metadata format3, private nonpersistence and all original full-goal gates. Task3 adds an independent accepted-write registry, generic orphaned-result routing and explicit Wait/QuitWithoutFinishing/Cancel; no new printing or automatic output is authorized by Quit.

- Task 2: Ruling: a blank compact start screen is not a printable document — retain its nil target and initialize the routing fixture with an owned about:blank page — cost if wrong: printing the start screen remains unsupported; a different window's page is never substituted.

- Task 3: Ruling: use asynchronous native Quit choices and track native printing as well as accepted file IO — a modal loop can obstruct IO callbacks, and native print preparation must not disappear from termination tracking when its source window closes — cost if wrong: additional prompt/operation identities and native keyboard/lifetime behavior to verify. Coalesce fast output before showing choices, ignore stale replies, and keep the explicit Quit action usable after Wait.

- Task 3: Ruling: non-browser result/Quit windows have no active browser store — the former normal-owner fallback could direct page shortcuts to an unrelated background document — cost if wrong: app-level commands may be unintentionally disabled, so keep updates/settings/new-window commands available and add owned-window/action regressions.

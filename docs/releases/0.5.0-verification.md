# Alcove 0.5 preview — verification and decisions

Source: b7139e58883f9cd0708118ec053819bb8e7a34ea, tag v0.5.0-preview.1.

This increment implements named WebKit profiles, encrypted per-profile libraries, durable clearing/deletion recovery, native profile controls and profile-owned Favorites. Selecting a shared Favorite keeps the current Space; assigning a different profile preserves the old profile’s collection. Imports commit Spaces and Favorites together; stale command-bar actions respect locked/pending controls.

264 browser checks passed, plus ZIP structure verification. Real loopback websites verify cookies/localStorage separation between two named profiles and private mode, background history, saved-store reuse, selective clearing and actual named-store deletion. Both optimized architectures compiled. The local universal DMG mounted, matched the ZIP executable and Info.plist, and passed signature/universal checks with the Applications link/readme present.

A fresh whole-branch review found no Critical issues and two paths initially labelled Minor. I treated both as functional defects and fixed them with nine failing-before/passing-after command/import checks and a green full package run. No deferred minors remain from that review. The review was source-based; it did not establish native visual quality.

CI: https://github.com/SinfulSoul007/alcove/actions/runs/42462909134 (passed at the released source revision).
Release workflow: https://github.com/SinfulSoul007/alcove/actions/runs/42463181857 (passed at the released source revision; public installers published).

The metadata upgrade retains encrypted session.sealed untouched and writes session-v2.sealed with the existing Keychain key. This prevents older previews dropping new profile fields. Changes in an older preview after migration are not merged. Clearing current history does not erase the retained migration copy, snapshots or backups. Unknown future formats refuse writes. Profiles separate website storage inside one macOS account; they do not restrict another person using the unlocked app.

Native 0.5 resizing, animation, keyboard, minimum-window and visual verification remain pending: Codex still denies access to Alcove Visual Four. The full browser goal remains active. Little Arc, routing/site search, Boosts/Easels, extensions, richer browser import/export/media/permissions, broader compatibility and performance work remain open. This preview is ad hoc signed, not Developer ID signed or notarized; no complete-security or Safari-speed claim is made.

## Rulings I made

1. Continue inline in the user's requested checkout/main under the existing explicit build/commit/push instruction and instruction not to stop; no redundant approval menu — cost if wrong is integration preference, not lost user data.
2. Repair global duplicate Space/live-tab UUIDs before pages exist — identical tab IDs could otherwise share a WKWebView across profiles; cost is fresh IDs for ambiguous corrupt entries, preserving their content.
3. Only rewrite normalized startup metadata if its canonical content changed — unconditional re-encryption broke preservation checks and added unnecessary disk work; cost is one in-memory canonical encoding comparison on startup.
4. Persisted valid profile IDs remain usable if a later metadata save fails, while unsaved/recovered IDs cannot create a persistent store — preserves live website login context without losing recovery identifiers; cost is temporary storage for an unrecoverable profile, with a visible message.
5. Add durable pending-data-clear state, not only deletion markers, and a process-wide per-profile operation registry — closing/reopening a window must not allow overlapping WebKit removals or stale callbacks overwriting new metadata; cost is an explicit retry after interrupted operations.
6. Retry a pending clear without repeating its original metadata reset — links queued after the first reset must survive; cost is retaining those newly queued tabs for loading after clear completes.
7. Successful unlock preserves matching live Space/tab identities and latest in-memory changes; fresh unsaved Spaces merge separately — avoids duplicate or resurrected tabs and preserves live forms when their profile agrees; cost is preferring the running window's state for known matching identities.
8. Wait up to five monotonic seconds for weakly tracked discarded pages before removing a named store; keep a tombstone on timeout/failure — WebKit requires those pages to release; cost is bounded deletion latency or retry, not silently recreating storage.
9. Favicon requests use a bounded header/body fetch and reject redirects to retain the documented same-origin request boundary; cost is a fallback icon for redirect-only endpoints.
10. Separate lifecycle and real-website checks into their own executables and add focused website-test/lifecycle-test modes — isolates fixture resources and shortens diagnostics; cost is extra test compilation in the full suite.
11. Save profile metadata in session-v2.sealed and retain session.sealed encrypted and unchanged — older binaries cannot drop unknown registry fields from the new file — cost is retaining an older recovery copy whose history is not erased by clearing the current file, plus no auto-merge of subsequent older-preview edits.
12. Move Favorites into a profile-owned canonical library collection with at most one mounted live tab — Space reassignment must not transfer a profile's Favorites, and clicking a shared Favorite must keep the current Space — cost is an optional-field migration and explicit collection updates during moves. Official archived Arc guides support profile ownership; native object reuse is our implementation choice.
13. Fix both reviewer-labelled minors as functional defects — an import must show its Favorites immediately and commit once to its captured profile; stale command-bar actions must honor locked/pending controls — cost is stricter action availability and a synchronous encrypted import commit.

Deferred minors: none.

# Native WebExtension development checkpoint

This source checkpoint continues the developing 0.9 integration. It adds engine interfaces and generated-fixture coverage; the Extensions manager, toolbar controls and user shortcut/menu wiring are still being built. It does not publish a release or change the installed sidebar preview and its separately verified `fb327eb` download.

Associated private windows expose their actual transient tabs and windows only to extensions explicitly approved in the owning normal profile. Native privacy classification is immutable, including before approval and after revocation. Separate private clients retain separate temporary website storage. Browser operations do not copy private URLs into the normal saved document.

Action summaries read the native label, badge, enabled state and icon. Native popup/background execution follows the actual main, Quick or explicitly approved private source. The popup closes on source navigation, closure, revocation or host retirement. A second click toggles the current popup; stale, foreign, duplicate and delayed callbacks cannot open one in another source. Pending preparation is bounded, and the native presenter respects Reduce Motion.

An approved spanning extension can present its shared native interface in a private window. That interface uses the extension's normal profile settings and sign-ins; the private website keeps its separate temporary cookies, local storage, user-content controller and live form. A private-only window can retain its auxiliary normal-owner lease without opening a normal window or requesting a private metadata key. An extension allowed in private can itself retain or transmit private information. Extension tabs/options in private and split-private runtimes remain unavailable.

An explicit private reload backend can associate an existing temporary session with an approved normal account, or reload it without extensions. Its native review explains form/history loss, closed Peeks, retained temporary website cookies and shared extension settings. It prepares the new account before replacing any views, uses a fresh private user-content controller and retains the same temporary website store. Cancellation, timeout, source navigation, private clearing, changed approval and a locked or damaged destination preserve the previous page and association. Main and Quick pages reload together only after consent. User-facing controls and displayed-sheet QA remain required.

Authorized native Peek navigation now changes extension/website configurations under the same tab identity. Ordinary websites retain WebKit's web-accessible-resource checks: exposed resources load, private resources and foreign-controller access fail. A regular website popup preserves real opener messaging. Extension-origin website popups remain an [unfinished compatibility gap](../research/webkit-extension-popups.md); refusal keeps the existing page and cannot rewrite its saved URL. Related blank popups retain their native opener, and Shift-click can open an ordinary Peek without replacing the source.

Native commands require their actual focused account, window and active tab. Reserved action commands reuse the popup source. Keyboard-event matching rejects autorepeat, foreign windows, additional modifiers and shortcuts claimed by multiple loaded extensions. Tab menus preserve the real native hierarchy, state and target, fetch current state when opened and check the captured source again before execution. A suspended background tab can expose and execute its menu without creating a website view. These host interfaces still await their user-facing controls.

Native permission callbacks bind the actual document, view, window, account, controller, code revision and approval. A review can grant declared API or website access for up to five minutes. Navigation, source closure, revocation, timeout, disablement and shutdown invalidate pending replies and temporary grants. These choices are not serialized into saved permissions. An approved spanning extension shares runtime permissions across its approved normal and private pages; the review explains that scope.

WebKit rounds permission expiration dates through its native time representation. Revocation compares the actual native values installed by the grant, preserving unrelated permanent rights. Temporary `activeTab` approval now works through the native gesture gate; ending it clears derived tab access when no native `activeTab` permission remains. Actual document-start callbacks reconcile grants and popups synchronously, and detaching a host shuts down its native contexts while keeping ordinary website views mounted.

Window focus notifications follow main/Quick changes. A shared main window is focused only for its selected account; returning from Quick updates the native extension API.

Removal persists a disabled retry entry and unloads its approved context before tearing down that extension’s open tabs, Peeks and related blank popups. Captured popup and closing-page identities survive URL changes. Removal waits for those native views to release before erasing their origin; a retained view leaves the entry pending for explicit retry. Generated fixtures preserve another extension’s options document, related blank popup and native settings, plus ordinary website forms and cookies.

Native erasure uses only Alcove-generated maintenance resources and public APIs under the exact owned controller and runtime identifiers. It clears extension storage, saved content scripts, request rules and extension-origin website stores without executing or trusting installed package code. Missing or modified package files can still be removed; unsafe ownership paths remain blocked. A blocked native database keeps its worker and metadata-writer lease alive independently of a cancelled waiter; an uncertain native result reserves that namespace until process restart. A failed final save retains the encrypted retry entry, revoked approval and package resources. A fresh metadata owner can finish the retry without a late old result overwriting its saved data.

Profile clearing follows retained controller namespaces, including structurally attached private views after normal-host retirement, and includes native records from interrupted installs absent from the current catalog. It revokes installed approvals and rotates the current controller identity only in the successful final metadata transaction. Private website views, forms and temporary cookies remain intact. Profile deletion erases its old native namespace before removing the named website store and controlled packages; unfinished operations remain paused and retryable.

## Remaining work

- Private extension tabs/options are refused before publication. A normal context configuration is tied to its extension process/store; substituting the private website store raises a native exception. A separate private extension-page runtime remains unfinished.
- Split-private extensions cannot receive private approval through the current spanning bridge. Their normal-only runtime can be approved separately.
- WebKit supplies no source tab for `browser.permissions.request`, even from a real options tab. Alcove conservatively denies that request. Explicit optional-permission review in the forthcoming manager remains required.
- Extension-to-website popup interoperability, private reopen controls and displayed-sheet QA, end-to-end removal/retry controls, native installation/update/permission controls, and store-download transport remain unfinished.
- Generated fixtures establish the tested boundaries. They do not certify third-party compatibility, complete Arc parity, an independent security audit or Safari performance parity.

The native engine requires macOS 15.4+. The browser retains its macOS 14 minimum, existing sandbox entitlements and Keychain policy. Public 0.8 metadata/download verification remains separate from developing 0.9 format 5 data.

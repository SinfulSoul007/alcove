# Native WebExtension development checkpoint

This source checkpoint continues the developing 0.9 integration. It does not publish a release or add a finished Extensions manager. The installed sidebar preview and its download remain the separately verified `fb327eb` checkpoint.

Associated private windows now expose their actual transient tabs and windows only to extensions explicitly approved in the owning normal profile. Native privacy classification is immutable, including before approval and after revocation. Separate private clients retain separate temporary website storage; explicit window targets, account isolation, normal-window closure, final private-window closure and stale adapters are exercised with generated extensions and local pages. Private URLs are not copied into the normal saved document by browser operations.

Native permission callbacks require the actual source document, view, window, account, controller, code revision and current approval. A review can grant declared API or web-site access for up to five minutes. Navigation, source closure, revocation, timeout, disablement and shutdown invalidate pending replies and temporary grants. These runtime choices are not serialized into saved permissions. An approved spanning extension shares these temporary permissions across its approved normal and private pages; the review explains that scope. An extension allowed in private can itself retain or transmit information.

WebKit rounds permission expiration dates through its native time representation. Revocation compares the actual native values installed by this grant, preserving unrelated permanent rights. A controlled date-round-trip regression and repeated real document navigations cover this boundary.

Window focus notifications now follow actual main/Quick focus changes. A shared main window is focused only for its selected account; returning from Quick to an existing main window updates the native extension API.

## Remaining work

- Private extension-origin pages are refused before tab/view publication. Reusing a normal context configuration with a temporary website store raises a native exception; borrowing the normal store would violate private website isolation. A separate private extension-page runtime remains unfinished.
- Extensions declaring split private runtimes cannot receive private approval through the current spanning bridge. Their normal-only runtime can be approved separately.
- WebKit supplies no source tab for `browser.permissions.request`, even when a real options tab calls it. Alcove conservatively denies the request. Explicit optional-permission review in the forthcoming manager remains required.
- Action popups, commands/context items, complete profile/uninstall runtime-data erasure and retry, explicit private reopen controls, installation/update manager and store-download transport remain unfinished parts of the implementation plan.
- Generated fixtures establish these tested boundaries; they do not certify third-party extensions, complete Arc parity, an independent security audit or Safari performance parity.

The native engine requires macOS 15.4+. The browser keeps its macOS 14 minimum, existing sandbox entitlements and Keychain policy. Public 0.8 metadata/download verification remains separate from developing 0.9 format 5 data.

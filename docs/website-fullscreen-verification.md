## Implemented and observed

Actual browser-page configurations enable the public Fullscreen API through the real-page `SplitDropWebView` initializer. Reader/internal views use their separate restricted configurations. Per-view residency captures the logical browser window, profile/presentation and latest intended host. It preserves WebKit's borrowed view and placeholder through SwiftUI remounts, resizing and host replacement. Reconciliation uses public state/view-move signals, runs after the native operation returns, and waits for the captured fullscreen window to disappear. The original host's weak restoration registry supplies the later native subview-removal signal; no private class name or timed delay is used.

The native witness exercises generic-element and playing-video Fullscreen API requests in tabs, actual native split panes, primary Peek, Quick Browse and Quick Peek, each in normal and private contexts. It checks separate native-window borrowing, logical window/profile identity, resize/remount, a replaced host, actual viewport, exact live view/document token, unsaved form, scroll and navigation history. Repeated entry waits for real native-window completion. No user profile, Keychain, global desktop input or process tracing is used.

Real production browser windows now also prove repeated Escape, Peek Escape precedence, address and Find text focus, captured-tab and last-window closure without quitting, ready Reader in the restored original window, and settings/customization/library restoration. Print/PDF/webarchive menu commands remain available during fullscreen and restore the captured document/window before output. PDF/archive use actual WebKit capture; the fixture witnesses and cancels the destination/print boundary. This does not establish visual native-panel behavior.

New Tab, sidebar visibility, recent-tab switching, next Space and split actions also restore native fullscreen before changing the visible browser. Their original registered page, document identity and unsaved form survive. The next-Space fixture uses a real local page in an adjacent Space of the same owned profile.

Actual file-picker and consent sheets now attach to the restored logical browser window, block conflicting address UI, cancel once, reject repeated results and retain their source profile/document/form. Ownership is captured before exit and rechecked before delivery and before returning a result. Existing same-URL replacement/handoff/Quick promotion and genuine file-input regression checks remain green on the prior source recorded above. Genuine HTTPS getUserMedia/OS device authorization is separate open scope.

Actual page alerts, confirmations and text prompts use asynchronous sheets on their captured logical browser window. WebKit's immediate exit hides native fullscreen before the delegate runs, but keeps state active until the JavaScript reply; the sheet uses this validated hidden-native interval without reparenting the borrowed view. After the reply, state0 plus disappearance of the captured fullscreen window permits restoration from that same hidden native window or a detached container. The exact source page/profile/document/form returns. Sheets block conflicting address UI; real Cancel, submitted/default text and all three dialog types are exercised in regular/private primary and Quick windows. Further stale-dialog and retirement lifetimes remain open.

# Portable saved-page export

The full browser goal includes moving a person's saved pages to another browser. Existing HTML import preserves folder structure, but Alcove has no export action. This increment adds **File → Export Bookmarks HTML…** for the normal window's selected profile. Normal implementation choices are delegated by the user's standing instruction to continue building without routine questions.

The exported Netscape bookmarks HTML contains Favorites, one group per Space with its pinned pages and complete folder hierarchy (including collapsed/empty folders), then remaining library bookmarks. Pins use their saved home address and custom/pinned title. Repeated URLs in different user folders remain; library records already represented by a pin/Favorite are not duplicated in the final group. Today, history, closed tabs, archives, deleted Spaces, cookies, credentials and other profiles are excluded. Reject credential-bearing/unsupported URLs with an explicit skipped-link count. Exported text/attributes must be escaped. Bound the complete output to 64 MiB and folder depth to 32; a bound failure writes no partial file.

The user chooses a destination through the native HTML save sheet. Capture its profile before opening the sheet; cancellation, source-window close or loss of profile availability prevents an unaccepted export. On acceptance, capture that profile's immutable bytes and write atomically off the main thread, using the existing output coordinator to track the accepted write through window closure and Quit. Failed output cancels a waiting Quit and reports a generic file failure without exposing a closed/private profile's content. The normal filename is `Alcove Bookmarks.html`; exported files are ordinary readable HTML outside metadata encryption. No private-window or extension-popup export, implicit destination, remote service or metadata-format change.

Approaches considered: a flat library export is simpler but drops Arc-style saved folder organization; serializing the whole browser document exposes unrelated metadata and is not portable. The chosen format is standard HTML containing only the selected profile's saved pages. This is an implementation choice within the already authorized browser scope.

Core serialization and real import round trips can be verified without an interactive desktop. Native profile/sheet/Quit behavior requires owned native fixtures and a live VM for final dialog checks. The public 0.20 tag and packages stay frozen; this increment is not release-ready until its relevant gates pass.

# Site Boosts

Alcove needs Arc-style website customization as part of the full browser goal: no-code colors/fonts, CSS and JavaScript, element hiding/undo, multiple saved looks and portable appearance sharing. This plan builds those local workflows. Native visual fidelity, remote galleries/sync and the other browser requirements remain open.

## Approach and constraints

Implement in the existing Swift/SwiftUI/AppKit/WebKit app, macOS14 minimum, metadataformat3, no dependencies/private APIs and exactly the existing six entitlements. Keep the stable live-review bundle and public0.6.2 downloads unchanged. Develop source0.7.0/build12/candidatev0.7.0-preview.1 only at final integration, with no new tag/release in this plan. Work inline/main under the standing user preference; no design or per-task agent gates. One fresh final whole-plan review and one Important/Critical RED→GREEN pass.

Choices made by the implementer: retain constructed CSSStyleSheet objects in an isolated content world because ordinary style elements fail under strict CSP; use page-world JavaScript, syntax-compiled by an owned JavaScriptCore context before inserting it into a separate inner async function. Passing arbitrary raw code after a native guard was experimentally unsafe. Page-world eval alone fails strict CSP; isolated-only JavaScript loses page globals, so neither is the selected primary implementation. Never interpolate CSS/selectors/hosts into executable source; pass typed arguments. Tests must verify the parsed-inner-function construction against escape and hoisting attacks, not assume native functionBody is a parser boundary.

## Data and matching

Optional BrowserLibrary.siteBoosts per profile and optional Preferences.boostsEnabled (nil means true). Private windows start with an empty temporary catalog and never inherit normal approvals. Each SiteBoost has UUID, editable BoostContent(name,host,appearance,css,javascript), enabled, hiddenSelectors and optional approvedJavaScriptHash. Approval is a SHA256 of exact UTF8 code, canonical host and boost UUID; profile binding comes from the owning library, with approval cleared on ID collision repair or portable import.

Match the exact canonical HTTP(S) hostname, including numeric/IDNA/IPv6 aliases; no implicit wildcard/subdomain matching. Host scope spans ports and HTTP/HTTPS and must be stated in the editor. Shared WebOrigin validates scheme/host/port0...65535 before any match; reject unusable Equals route ports too (the earlier deferred M1). A single enabled Boost per host/profile; other saved variants remain available. Catalog cap64; CSS64KiB, JavaScript32KiB; names1...80 characters, no controls; selectors64, each1...1024UTF8 bytes without controls; aggregate catalog payload1MiB. Colors are optional #RRGGBB; font is an enum (original/system/serif/mono/rounded); text scale0.75...1.75. Invalid saved records are repaired deterministically without changing another profile's records. ID collisions preserve different records with new IDs and no approval. Editing host/code clears approval; editing colors/name/CSS does not grant it. Preserve exact user CSS/JS including whitespace.

Portable JSON appearance sharing through explicit clipboard Copy/Paste actions contains a versioned content subset (name,host,appearance,css,hiddenSelectors), never JavaScript/approval/IDs/enabled. Limit1MiB; reject unsupported versions/malformed/over-limit input, import disabled with fresh UUID. No remote fetch. Global off, per-Boost toggle, delete and Undo all persist before changing any page; failed writes leave data and DOM intact. Clear website data retains customizations like bookmarks; deleting a profile deletes its catalog. Recovery/relaunch preserve encrypted content and approvals. Normal and private writes follow existing candidate-commit boundaries.

## Runtime

Install one idempotent, generic main-frame document-start script/weak handler into every owned normal/split/Peek/Quick WKWebView, including supplied popup configurations. It carries no profile-specific CSS/code. A per-document nonce in the isolated world binds bridge messages and async work; native resolves message.webView's current BrowserStore/profile/lifetime, main-frame origin, live document nonce and URL before retrieving the current catalog. Closed, foreign, stale or unavailable pages are ignored. Reused/shared content controllers cannot leak profile definitions or retain stores/views. Preserve non-Alcove scripts.

Update/remove retained constructed sheets in place at ready time and after successful edits. CSS parsing errors surface without removing the prior valid style. Generated appearance CSS and hidden selectors precede custom CSS, with hidden selectors last so user CSS cannot accidentally unhide zapped nodes. Styles target the main document; cross-origin frame contents/shadow roots are not silently advertised as styled.

User JavaScript needs explicit window-bound approval showing host/profile and code. Snapshot/revalidate UUID+host+code/profile/source lifetime after the prompt; edits/deletion/profile switches cannot reuse consent. Validate code syntax without running it in JavaScriptCore. A second generic page-world document-start script creates an immutable, nonconfigurable random nonce before page code. Native validates the isolated bridge nonce around reading this page nonce; the two bind the same document. The outer native function checks exact location protocol/hostname and the immutable page nonce immediately before running the prevalidated inner async function in the page world. Record execution per document+boost+code hash before awaiting, so duplicate bridge events never run it twice. Approval applies on future loads; an explicit Run on This Page action may run it once now. No reload on edit/toggle. Disabling stops future execution but cannot undo arbitrary JavaScript effects; explain that reload may be needed. Never execute unapproved code.

Zap mode requires a saved enabled Boost, frozen current visible source/profile/document/nonce and a picker nonce. Hover outlines a candidate; clicking prevents page activation and sends a bounded unique CSS selector through the isolated main-frame bridge. Escape/Done exits. Native saves selector before hiding; failed/stale/foreign messages leave DOM intact. Undo removes the last selector and restores the same DOM node and form state; no DOM deletion. Validate selectors with the engine before saving. Picker state is canceled on navigation/close/profile/lifetime changes, and Escape must honor IME before picker cancellation and before Peek dismissal. Test shared controllers, old messages, duplicate click, writes failing, profile switches and native source-window close.

## Native experience and evidence

Entry via command, Settings and primary/Quick action menus, without expanding the cramped navbar. Editor shows explicit site/profile, saved variants, on/off, color pickers, font/scale, presets/shuffle, CSS/JS editors, approval status, hide/undo and Copy/Paste appearance. A Quick/Peek source must remain frozen rather than retargeting the current Space. Invalid, stale or dirty drafts show recoverable errors; Done saves a valid dirty draft, Cancel Edit discards explicitly. A compact picker banner shows Done/Undo while the page stays interactive.

Owned core/store/WebKit/native-host tests prove bounded persistence, rollback, DOM and scope behavior. Full existing suite and both optimized architectures/signature/Info/six-entitlement gates are required; inspect exact pushed-source CI and package evidence. Owned renders do not prove native animation, focus, accessibility, Arc fidelity, everyday site compatibility, performance or fresh install. Keep all those original gates visible and the whole-browser goal active until verified.
